# Contributing to BHG-Knowledge

> **El conocimiento bien organizado multiplica el valor de las ideas.**

---

# Purpose

This document defines the official contribution process for the BHG-Knowledge repository.

Every contribution must improve the quality, traceability and long-term value of the knowledge ecosystem.

Contributors are expected to preserve consistency rather than maximize speed.

---

# Guiding Principles

Every contribution shall follow these principles:

- Preserve knowledge.
- Maintain traceability.
- Prefer clarity over complexity.
- Document reasoning before implementation.
- Improve existing knowledge before creating new knowledge.
- Avoid duplication.
- Respect repository standards.
- Think in systems instead of isolated documents.

---

# Contribution Philosophy

Knowledge is never created in isolation.

Every new contribution must integrate naturally with the existing ecosystem.

Before creating something new, contributors shall verify whether:

- the idea already exists;
- the problem has already been studied;
- a similar solution has already been documented;
- the contribution belongs somewhere else.

---

---

# Human Contributions

Human contributors are expected to:

- provide sufficient context;
- explain reasoning;
- avoid undocumented assumptions;
- cite reliable sources when applicable;
- follow repository standards;
- preserve document history.

---

# AI Contributions

Artificial Intelligence assistants are collaborators.

They do not replace human judgment.

AI-generated content must:

- follow repository standards;
- remain deterministic whenever possible;
- explain assumptions;
- avoid hallucinated information;
- preserve traceability;
- never overwrite human decisions without explicit approval.

---

# Documentation Rules

Every new document should answer:

- Why does it exist?
- What problem does it solve?
- Who governs it?
- What documents does it govern?
- What future documents does it enable?

---

# Commit Rules

Commits should:

- be atomic;
- represent one logical change;
- follow Conventional Commits;
- include meaningful descriptions;
- preserve repository history.

Examples:

docs(readme): improve repository introduction

docs(governance): add engineering principles

feat(bkos): introduce knowledge indexing model

---

# Pull Requests

Every Pull Request should describe:

- objective;
- motivation;
- affected documents;
- compatibility;
- future impact.

Large unrelated changes should be avoided.

---

# Knowledge Preservation

Knowledge should never be deleted without justification.

When knowledge becomes obsolete:

- archive it;
- reference its replacement;
- preserve historical context whenever possible.

---

# Quality Expectations

Every contribution should improve at least one of the following:

- clarity;
- consistency;
- traceability;
- maintainability;
- scalability;
- knowledge quality.

---

# Future Automation

This repository is designed to support future automation through:

- GitHub Copilot
- ChatGPT
- Claude
- Future BKOs agents

Automation must always respect repository governance.

---

# Final Principle

Contributors do not simply write documents.

They help build the permanent memory of Breto's Holding Group.
